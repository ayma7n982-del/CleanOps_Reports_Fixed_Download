# وجهة النقلة من سجل المكبات الفعلي

- قائمة المكبات مصدرها `dumpsites` باستعلام `isActive == true` دون حد نتائج ثابت، مع تحديث مباشر وذاكرة Firestore المحلية.
- يجب اختيار وجهة صراحةً. البحث بالاسم أو الموقع. إغلاق المكب أو اختفاؤه من القائمة يلغي اختياره؛ لا يُختار بديل تلقائيًا.
- تحفظ النقلة `dumpsiteId` و`dumpsiteName` و`dumpsiteLocation`، مع إبقاء `landfill` للتقارير الحالية. لا تعديل للنقلات القديمة.
- تحفظ `requestedDumpsiteId` عند التسجيل، ثم يطبق تحويل المسار حسب المعرّفات. الوجهة والعنوان والنشاط تشير إلى المكب النهائي الفعلي، مع `routeDecisionId` لتتبع القرار.
- دون اتصال، تُستخدم القائمة المخزنة، وتدخل النقلة طابور المزامنة الحالي. أول استخدام يحتاج تحميل المكبات مرةً واحدة. رفض الصلاحية يظهر رسالة واضحة ويمنع التسجيل بوجهة غير مؤكدة.
- صلاحيات إضافة/تعديل المكبات للإدارة لم تتغير. أضيفت قراءة المكبات النشطة فقط للمشرف النشط المرتبط بمجموعة. العامل والحساب المعطل وغير المسجل يبقون ممنوعين.

## فحص التغيير

اختبارات Flutter: `test/trip_dumpsite_test.dart` و`test/trip_dumpsite_picker_test.dart`؛ تغطي الاختيار والبحث والذاكرة المحلية والقائمة الفارغة وتغيير الاسم وتكرار الأسماء وتحويل المسار والتعارضات.

اختبارات Firestore ضمن `firebase/tests/firestore.rules.test.cjs`: القراءة المسموحة، رفض الاستعلام غير المصفّى، رفض المكبات غير النشطة، الحساب المعطل أو المحذوف أو غير المرتبط بمجموعة، ورفض انتحال/تغيير/حذف المكبات.

## خطة التفعيل الإنتاجي

1. مراجعة فرق `firebase/firestore.rules`؛ التغيير المقصود هنا يقتصر على قراءة المشرف للمكبات النشطة. مقارنة أي تغييرات أخرى في `main` مع القواعد المنشورة قبل النشر.
2. اجتياز اختبارات المحاكي وFlutter على النسخة المراد نشرها، ثم الحصول على اعتماد نشر قواعد مشروع `nrc-aid` وفق `AGENTS.md`.
3. تشغيل مسار `Deploy Firestore rules (manual)` المراجع الذي يعيد اختبار القواعد قبل نشرها؛ لا تغيير في Storage أو Functions أو SMS لهذا الإصلاح.
4. تثبيت APK ناجح البناء، وفتح النقلات بحساب مشرف: إضافة مكب من الإدارة، اختياره، تعطيله، تجربة مكبين بنفس الاسم، ثم تسجيل نقلة للمكب الصحيح والتحقق من المعرّف المحفوظ.
5. تحميل المكبات ثم قطع الاتصال وتسجيل نقلة وإعادة الاتصال؛ التحقق من سجل واحد وتأكيد المزامنة. تجربة تحويل مسار إداري والتحقق من معرّف الوجهة النهائية.
6. عند مشكلة صلاحيات، استعادة نسخة القواعد السابقة المراجعة. البيانات القديمة لا تحتاج ترحيلًا.

حفظ قواعد في GitHub لا يعني نشرها على Firebase. نجاح اختبار واجهة بالبيانات المحاكية لا يثبت تجربة هاتف أو مزامنة إنتاجية.
