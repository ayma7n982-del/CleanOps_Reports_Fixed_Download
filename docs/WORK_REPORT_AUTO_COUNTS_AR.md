# تقرير العمل من سجلات المصدر

التقرير اليومي الجديد يجمع أعداده من سجلات `operations` حسب المجموعة والتاريخ والوردية. التقارير السابقة تحتفظ بأرقامها دون إعادة كتابة.

- استماع مباشر كامل لسجلات المجموعة دون حد ذاكرة العمليات العامة، مع توضيح حالة المصدر المحلي وتأكيد الخادم.
- اعتماد هوية العامل وقائمة `WorkerRoster` الموحدة الجديدة، مع ربط معرّفات الحسابات المستصلحة بمعرّفاتها القديمة عند وجود دليل هوية صريح فقط.
- السجل المتكرر بالحالة نفسها يُحسب مرة واحدة؛ تعارض الحالات يتطلب تصحيح المصدر. الغياب والإجازات والأذونات والمهمات الخارجية منفصلة.
- النقلات المكتملة وحدها تدخل في الإنجاز؛ الجارية والملغاة تظهر منفصلة. النقلة تتبع يوم بدئها حتى لو أغلقت بعد منتصف الليل.
- النقص أو السجلات دون وردية أو هوية أو حالة صحيحة تظهر بوضوح. غياب كشف الحضور أو غياب تأكيد المصدر لا يتحول إلى أصفار وهمية.
- فحص اكتمال كشف اليوم يستخدم قائمة العمال الموحدة؛ لا يُستخدم تعداد اليوم لاستنتاج غياب تاريخي بعد نقل العمال.
- طابور المزامنة يتراكب فوق المصدر. حفظ مسودة دون اتصال متاح؛ مراجعة الإرسال تتطلب تأكيد المصدر.
- عند الإرسال تُقرأ السجلات من الخادم وتعرض للمراجعة ثم يعاد فحص تغيرها. تُحفظ الأعداد وبصمتها ومعرّفات سجلاتها في `sourceSnapshot`، وتبقى النسخة المرسلة ثابتة بعد ذلك.
- زر صياغة الملخص يستخدم الأرقام محليًا دون API ولا يستبدل النص المكتوب.

الحدود: منع التقارير المكررة يعتمد على البيانات المتاحة ولا يعد قفلًا موزعًا بين جهازين غير متصلين. المراجعة ليست معاملة ذرية مع تعديل سجلات المصدر؛ تمثل آخر قراءة مؤكدة. لا تتغير قواعد Firebase أو وظائف الاعتماد أو صلاحيات الأدوار؛ الحفظ يستعمل طابور المزامنة ومسار الاعتماد الموجودين.

اختبارات الحساب والنطاق والتكرار والتعارض والهوية والتوقيت، وعرض الهاتف، واستعادة الطابور: `work_report_summary_test.dart` و`work_report_summary_card_test.dart` و`work_report_sources_test.dart`.
